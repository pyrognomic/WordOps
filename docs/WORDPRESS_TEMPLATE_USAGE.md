# WordPress Provisioning Templates

This document describes the `--template` feature implemented for `wo site create`.

Source of truth in code:
- `wo/cli/plugins/site_create.py`
- `wo/cli/plugins/site_functions.py`

## Where It Applies

Command:
- `wo site create <domain> --wp --template <FILE>`
- Also works with `--wpfc`, `--wpsc`, `--wprocket`, `--wpce`, `--wpredis`, `--wpsubdir`, `--wpsubdomain`

Guardrails from code:
- Template is only accepted for WordPress site installs.
- Template is rejected for non-WordPress site types.
- Template is rejected for `subsite` creation mode (`--subsiteof`).

## Processing Pipeline

1. `site_create.py` detects `--template` and calls `load_wp_template()`.
2. JSON is parsed/validated.
3. During WordPress setup, after core install and cache plugin setup, `apply_wp_template()` runs.
4. Template actions execute in this order:
   - themes
   - plugins
   - global `options`
   - global `constants`

## Template JSON Schema (Implemented)

Top-level object:
- `themes` (array, optional)
- `plugins` (array, optional)
- `options` (object, optional)
- `constants` (object, optional)

### `themes[]` entries

Each entry must be an object and include at least one of:
- `slug`: WP.org theme slug or activation name
- `url`: local zip path or URL used as install source

Optional keys:
- `activate`: boolean (default `false`)
- `network`: boolean or omitted (used for multisite enable flow)

### `plugins[]` entries

Each entry must be an object and include at least one of:
- `slug`
- `url`

Optional keys:
- `activate`: boolean (default `false`)
- `network`: boolean or omitted (used for multisite activation flow)
- `options`: object mapping option key -> value

### `options`

Object map of WP option updates.
Applied with `wp option update <name> <value>`.

Serialization behavior:
- dict/list -> JSON string
- bool -> `1`/`0`
- other types -> string conversion

### `constants`

Object map of constants written via `wp config set`.

Serialization behavior:
- bool -> `true`/`false` with `--raw`
- int/float -> raw numeric
- string -> quoted string

## Minimal Example

```json
{
  "themes": [
    {
      "slug": "astra",
      "activate": true
    }
  ],
  "plugins": [
    {
      "slug": "nginx-helper",
      "activate": true,
      "network": true
    }
  ],
  "options": {
    "blogname": "Example Inc.",
    "timezone_string": "America/New_York"
  },
  "constants": {
    "WP_CACHE": true,
    "WP_MEMORY_LIMIT": "256M"
  }
}
```

## Usage Examples

```bash
# Standard WordPress install with template
wo site create app.example.com --wp --template docs/examples/wp-template.json

# Multisite install with template
wo site create network.example.com --wpsubdir --template docs/examples/wp-template.json

# Combined with SSL setup
wo site create app.example.com --wp --template docs/examples/wp-template.json -le --hsts
```

## Validation Errors You Can Hit

Generated by `load_wp_template()` and related helpers:
- file does not exist
- invalid JSON
- top-level JSON is not an object
- `themes`/`plugins` is not an array
- item in `themes`/`plugins` is not an object
- theme/plugin entry missing both `slug` and `url`
- `activate`/`network` not boolean
- plugin `options` not object
- top-level `options`/`constants` not object

## Operational Notes

- Theme/plugin install source is `url` if present; otherwise `slug`.
- Activation target uses `slug` when present; otherwise fallback label.
- Existing cache plugin setup in WordOps runs before template application.
- Template plugin `options` are applied after each plugin install.

## Related Code

- Loader/validator: `load_wp_template()`
- Applicator: `apply_wp_template()`
- Install helpers: `installwp_theme()`, `installwp_plugin()`
- Option/constant writers: `update_wp_options()`, `define_wp_constants()`
